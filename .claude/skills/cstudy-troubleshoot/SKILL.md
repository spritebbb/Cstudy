# 排查 Cstudy 故障

用户**基本不会 Python**，看到报错只会把日志发过来。你的任务是替他把日志翻译成人话，
并且给出**具体到点哪里**的下一步。绝对不要把裸 traceback 丢给用户。

## 第一步：读证据

按顺序收集，不要跳过：

1. **日志**（主要证据）
   - `logs/cstudy.log` —— 当前日志，读最后 100 行左右
   - `logs/cstudy.log.1`、`.2`、`.3` —— 滚动归档，当前日志不够长时往前翻
   - 找 `[ERROR]` 和 `[CRITICAL]` 开头的行，那些才是真正的故障点
2. **配置** `config.yaml` —— 确认模型名、路径、转写开关等是否被改过
3. **密钥是否就位**：只看 `.env` 里**有没有** `DEEPSEEK_API_KEY` 这一项，
   **不要读出密钥内容，也不要写进任何回复或文件**
4. **环境状态**：需要时跑一次 `scripts/smoke_test.py`（见 `/自检`）

## 第二步：定位是哪一环

软件的主链路是：

```
导入链接 → 抓字幕 → 生成笔记 → 出题 → 入库
```

日志里会出现这些关键标记，对应关系：

| 日志里看到 | 卡在哪一步 | 常见原因 |
|---|---|---|
| `subtitle` / 字幕相关 ERROR | 抓字幕 | 没扫码登录 B 站、视频没有 CC 字幕且 whisper 没启用、cookie 过期 |
| `whisper` / `transcribe` / CUDA 报错 | 本地转写 | 显卡驱动或 CUDA 库缺失（应自动退回 CPU，若没退回是 bug）、模型没下载完 |
| `ai` / `openai` / `deepseek` ERROR | 调用 AI | 密钥错或余额不足、网络不通、模型名写错 |
| `429` / `rate limit` / 超时 | 调用 AI | 请求太频繁，等一会儿重试 |
| `sqlite` / `IntegrityError` / 数据库锁 | 入库 | 软件开了两个窗口、数据库文件被占用 |
| `ffmpeg` / `yt-dlp` 找不到 | 取音频 | 工具没装或 PATH 没生效（重启终端） |

## 第三步：说人话

回复按这个结构，**不要出现 traceback、堆栈、Python 术语**：

1. **一句话结论** —— 比如"卡在抓字幕这一步，因为 B 站登录态过期了"
2. **为什么会这样** —— 一句话，用生活化的类比
3. **现在怎么做** —— 明确到"双击哪个文件""点哪个按钮"，给可执行的步骤
4. 如果修不了，说明需要我改代码，并说清楚改哪里

日志里的技术细节可以附在最后（折叠成一小段引用即可），方便用户转给我看，
但**结论必须放在最前面**。

## 边界

- 只在读、不擅自改。要改代码或配置先跟用户说清楚再动手。
- 密钥内容永远不要出现在回复里。
- 如果日志里没有任何 ERROR，说明故障可能出在界面层：让用户描述"点了哪个按钮之后出现的"，
  并检查 `logs/cstudy.log` 里出错时间点前后 30 行的 INFO 记录。
